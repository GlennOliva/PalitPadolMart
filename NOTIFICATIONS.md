# PalitPaddleBai Mart - Notifications

Phase 12 provides durable in-app notifications for major marketplace events.
Business tables and immutable event rows remain the source of truth. PostgreSQL
triggers translate committed changes into recipient-specific notification rows
in the same transaction, so a later email delivery channel can consume the same
event boundary without changing commerce RPCs.

## Architecture

| Area | Location |
| --- | --- |
| Database migration | `supabase/migrations/20260913000000_phase12_notifications_google_oauth.sql` |
| Notification provider | `src/features/notifications/NotificationsProvider.tsx` |
| Query and mutation service | `src/features/notifications/notifications.service.ts` |
| URL filter parsing | `src/features/notifications/notifications-params.ts` |
| Role-aware destinations | `src/features/notifications/notification-routes.ts` |
| Bell and notification items | `src/components/notifications/` |
| Full notification center | `src/pages/account/NotificationsPage.tsx` |
| Hosted verifier | `verify-phase12.mjs` |
| Browser acceptance | `tests/e2e/phase12/` |

`NotificationsProvider` loads the five newest rows and an exact unread count.
It refreshes on authentication changes, window focus, and recipient-filtered
Supabase Realtime changes. Mark-one and mark-all actions update optimistically
and roll back if the controlled database mutation fails.

The protected `/notifications` page performs read/type filtering and ten-row
pagination in PostgREST rather than loading all rows into the browser. Its
state is represented by the `read`, `type`, and `page` URL parameters.

## Data Contract

Each `notifications` row contains:

- `recipient_id`: the only user who may read the row.
- `actor_id`: the authenticated actor when one applies.
- `event_name`: stable machine-readable event identity.
- `event_key`: stable delivery identity used for deduplication.
- `type`: `order`, `inquiry`, `dispute`, `review`, `report`, or `system`.
- `title` and optional `message`: safe display copy generated by PostgreSQL.
- `related_entity_type` and `related_entity_id`: role-aware navigation target.
- `is_read` and `created_at`: recipient state and stable ordering.

The unique `(recipient_id, event_key)` index makes trigger retries idempotent.
Ordering uses `created_at DESC, id DESC`; recipient/read indexes support the
header summary and paginated center.

## Event Matrix

| Source | Event names | Recipient |
| --- | --- | --- |
| Inquiry or reply | `inquiry.created`, `inquiry.reply` | Owning seller or counterparty |
| Order lifecycle | `order.created`, `order.confirmed`, `order.rejected`, `order.cancelled`, `order.preparing`, `order.shipped`, `order.ready_for_pickup`, `order.completed` | Owning seller or buyer, depending on the transition |
| Payment lifecycle | `payment.submitted`, `payment.cash_selected`, `payment.approved`, `payment.received`, `payment.rejected`, `payment.failed` | Owning seller or buyer |
| Review | `review.received` | Reviewed seller |
| Listing report | `report.created`, `report.under_review`, `report.resolved`, `report.dismissed` | Active admins for creation; reporter for status changes |
| Dispute activity | `dispute.opened`, `dispute.message`, `dispute.evidence`, `dispute.escalated`, `dispute.closed`, `dispute.resolved` | Counterparty and active admins where applicable |
| Refund activity | `dispute.refund_requested`, `dispute.refund_approved`, `dispute.refund_rejected`, `dispute.refund_completed` | Owning seller or buyer |
| Seller moderation | `seller.status_changed` | Seller account owner |

The actor is excluded from participant broadcasts. Report creation deliberately
does not notify the reported seller or expose the report id to that seller.
Admin report/dispute destinations are stored for Phase 13, but are not linked
to an admin page until those routes exist.

## Security

- RLS permits authenticated users to select only rows where
  `recipient_id = auth.uid()`.
- Direct INSERT, UPDATE, and DELETE are revoked from browser roles.
- `emit_marketplace_notification(...)`, legacy `notify_user(...)`, and every
  trigger function are not executable by `anon` or `authenticated`.
- Only `mark_notification_read(uuid)` and
  `mark_all_notifications_read()` are exposed to authenticated callers.
- Mark-one includes the recipient predicate and returns `false` for another
  user's id without disclosing whether that row exists.
- Event recipients, actors, subjects, statuses, titles, and messages derive
  from trusted persisted rows rather than browser-supplied notification data.

## User Experience

- The header bell exposes the exact unread count to assistive technology and
  visually caps counts above 99 as `99+`.
- The disclosure contains at most five newest notifications and supports
  Escape, outside-click dismissal, and focus restoration.
- Notification links resolve to buyer/seller-specific order and dispute routes.
- The full center supports all/read/unread and notification-type filters,
  pagination, loading, retry, mutation-error, and contextual empty states.
- Layout and touch targets are covered at 375, 390, 430, 768, 1024, and 1440
  pixel widths.
